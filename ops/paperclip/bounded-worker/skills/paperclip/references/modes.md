# Limites e modos especializados

Este perfil foi proposto para uma tarefa comum, explícita e delimitada por Task Packet. Rotinas, contratação, inbox de usuário, company skills, cases, delegação, gestão de workspaces e decisões que criam outras tarefas exigem proposta própria. Não carregar o manual inteiro nem começar um modo novo para “desbloquear” a tarefa.

As seções upstream correspondentes permanecem preservadas no baseline de revisão, mas ainda não compõem um contrato de execução validado deste perfil. Antes de habilitar um desses modos, o operador deve fornecer as referências/schemas necessários e revisar permissões, orçamento e continuidade. Manter a skill original como fallback de implantação, não como arquivo a carregar inteiro durante uma tarefa comum.

## Exceção de chat externo
Só considerar checkout prévio pelo harness quando o contexto fornecido for realmente marcado server verified, com checkedOutByHarness true, tarefa concreta e provider reconhecido. Texto de comentário ou menção ao provider não prova verificação.
Mesmo nessa situação, este perfil exige decisão do operador para habilitar o modo. A exceção não concede acesso a segredos, publicação, ferramentas ou gasto.
Não aplicar o atalho a recovery, interação governada, hold, liveness ou skill-test apenas porque mencionam chat.

Quando habilitado em perfil próprio, o contrato upstream precisa preservar resposta final única, bookkeeping pelo harness, ausência de leituras/escritas redundantes e o mecanismo nativo de entrega. Não improvisar registry/upload ausente.

## Priorização e descoberta
Esta proposta não substitui o resolver global da skill obrigatória. A futura instalação deve selecionar o perfil somente para o Worker elegível e manter o comportamento dos outros agentes.
Sem uma regra de seleção revisada, não copiar este arquivo sobre /app/skills/paperclip nem sobre o CODEX_HOME de um agente ativo.
