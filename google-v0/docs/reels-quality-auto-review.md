# Independent validation of saved candidates

The analysis worker can make one distinct validation request after saving the original response and normalized candidate. It never regenerates or edits that candidate. The default is closed: protected runtime configuration `reels_quality_validation_operation_ids` must be a finite list of exact existing operation IDs. The current rollout may contain only the previously authorized original100 operation. A request body, Reel content or model response cannot enable this setting. Existing owner, operation, import-hold, stage-pause and provider-boundary checks remain mandatory.

Validation is only attempted for a received candidate which failed the existing quality outcome. Already accepted literal candidates and pre-existing independent reviews do not need another call. The existing provider identity/model is reused in a separate independent context. This is an additional paid inference, not a replay of original acquisition, STT or analysis. It has separate immutable request, raw response, provider usage, policy and source bindings. Finance adds its measured usage separately; uncertain/missing usage stays unknown, never zero or confirmed billing.

Sources are full saved caption/transcript plus the unchanged candidate. For visual claims, the worker reads the exact saved video generation, verifies its checksum and extracts at most sixteen JPEG frames (maximum 500 KB each), selected at midpoints of referenced intervals. There is no Instagram download or STT call. The evaluator receives only those frames, never the original video or audio. Supported visual claims must be static and covered by reviewed frames in their cited intervals; continuous action, ordering and absence over time remain inconclusive. Complete text exceeding the input bound is not silently truncated. The quality gate, source identity checks, typed roles, temporal constraints and knowledge readiness are unchanged.

The server creates a durable intent before submission. One candidate/source/policy binding can dispatch at most once, including concurrent delivery, process interruption and timeout. No retry or automatic correction loop is added. An intent without a saved response is uncertain and cannot dispatch again. A received response is saved before parsing. A saved valid response can be finalized later without another model call. Negative receipts are preserved but do not occupy the immutable accepted-review selection, permitting a later independently approved editorial correction. Malformed responses remain preserved for diagnosis.

Automatic receipts use `server:saved-source-validation-v1`, an external provider execution identity and immutable artifact hashes. They never impersonate operator or native-editorial approval. Valid manual receipts take precedence. Recovery/import routes remain provider-free, retain `tools={}`, and cannot initiate validation for previously failed jobs. This package adds no endpoint for that purpose. Therefore the already-failed three candidates require their existing approved recovery path or a separately scoped future validation action; resuming them does not silently incur a charge.

Validation runs only in GitHub Actions with synthetic adapters; the task's implementation does not execute providers, media extraction, Google writes, product tests or builds locally. Real acceptance and an operation-limited configuration change remain required before rollout. The worker can reject individual candidates while the batch continues under its existing policy; this feature does not guarantee that all100 will pass quality.
